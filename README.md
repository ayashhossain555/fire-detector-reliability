# Shift-aware operating points for open fire and smoke detectors — code and artefacts

Ayash Hossain Chowdhury (ORCID 0009-0005-1522-7958). Companion repository for
the paper *Shift-aware operating points for open fire and smoke detectors*
(2026, under review; preprint DOI to be added here and in `CITATION.cff`).

## Summary

Twenty-four YOLOv8/YOLO11/RT-DETR-l detectors (n/s/m sizes, seeds 3407 and
1337, a patience-60 deviation run, de-duplicated and size-matched D-Fire
variants) were trained under one fixed protocol on D-Fire and Pyro-SDIS and
evaluated on four labelled splits from three domains (official and clean
D-Fire test, Pyro-SDIS, the Roboflow *final-fire-project* thesis set) plus
HPWREN FIgLib camera sequences. For every model-by-split cell the repository
holds the exported-detection calibration analysis (LaECE, D-ECE, LRP-FN,
identity/temperature/Platt/isotonic maps fitted on source and target
calibration splits, image-bootstrap intervals), the threshold-versus-map
decomposition, operating points, label-free threshold-transfer rules,
camera-disjoint conformal analysis and FIgLib time-to-detection. Everything
the paper reports is read from the JSON files in `artefacts/`; the scripts in
`scripts/` regenerate those files and the figures from the exported
detections and the datasets. This is the "accompanying repository" named in
the paper's Data availability statement.

## Layout

```
scripts/        every analysis script, verbatim (40 .py, 2 .sh, queue.json)
docs/           TRAINING-PROTOCOL.md, TOOLBOX-PATCHES.md, machine-written summaries (*.md)
artefacts/      machine-written JSON results, per-cell calibration folders,
                run records, figures, derived COCO ground truth, dataset indices
splits/         D-Fire image lists (clean test, calibration, de-duplicated and
                size-matched training lists)
toolbox_patch/  diff applied to fiveai/detection_calibration (commit bf59c92)
requirements.txt, CITATION.cff, LICENSE
```

## Pipeline order

1. `build_dataset_index.py` — index the downloaded datasets (counts, class order, hashes).
2. `parquet_to_yolo.py`, `make_thesis_gt.py`, `figlib_index.py` — export Pyro-SDIS, the thesis set and FIgLib to the YOLO/COCO layouts.
3. `make_coco_gt.py` — canonical COCO ground truth (`fire` = 1, `smoke` = 2; categories sorted by id), seeded calval/caltest halves.
4. `duplicate_audit.py`, `dfire_leakage.py` — pHash near-duplicate audit and D-Fire leakage; `make_dfire_dedup.py`, `make_dfire_sub.py` — de-duplicated and size-matched D-Fire training sets.
5. `train_queue.py` (`queue.json`, `train_run.py`, `write_runs_meta.py`) — the 26 runs under `docs/TRAINING-PROTOCOL.md`.
6. `export_predictions.py` — raw detections at conf 0.001, max_det 300, for every model x split (the 2.9 GB `detections/` folder; see Zenodo below).
7. `run_matrix.py` (with `run_calibration.py`, `calib_metrics.py`, `selftest_calibration.py`) — one calibration cell per model x split x map.
8. `bootstrap_ci.py` — image-level bootstrap intervals per cell; `summarise_matrix.py` — `matrix_summary.json/.md`.
9. `threshold_decomposition.py` -> `decomposition_fractions.py`; `operating_points.py`, `pyro_event_timing.py`, `pyro_negatives.py`; `camera_conformal.py`, `pyro_camera_overlap.py`; `figlib_eval.py`, `figlib_temporal_conformal.py`; `label_free_threshold_pilot.py` -> `label_free_threshold_refine.py` -> `label_free_revision.py` -> `label_free_clean_check.py` -> `label_free_holm_B10000.py`; `scale_seed_summary.py`, `dedup_training_comparison.py`.
10. `make_figures.py`, `make_figures_eaai.py` — figures into `artefacts/figures_paper/`.

`refresh_analyses.sh` runs steps 8-10 in order; `refresh_daemon.sh` re-ran
them after each completed training run. The scripts were run from an
`analysis/` folder with `coco_gt/`, `datasets/`, `detections/`, `runs/`,
`runs_meta/`, `calibration/` and `detection_calibration/` as siblings and
`../data/<dataset>_yolo/` holding the images; absolute paths in some shell
scripts and in the `abs_path` / `layout` keys of the artefacts are the
author's machine and must be adapted.

## Split lists (`splits/`)

Plain text, one D-Fire image file name per line, sorted. The names are the
official D-Fire file names, so each list applies to a fresh download.

| File | Images | Derivation |
|---|---|---|
| `dfire_calval.txt` | 1,722 | Seeded 10 % of the official D-Fire training split (`random.Random(3407)`), removed from training and used as the D-Fire calibration split. Written from the `file_name` fields of `artefacts/coco_gt/d_fire_calval.json` (`make_coco_gt.py`; the seeded move is recorded in `artefacts/datasets/d_fire_yolo.json`). |
| `dfire_test_clean.txt` | 1,991 | Official test images with no training image within pHash Hamming distance 8 (`dfire_leakage.py`; pHash from `artefacts/datasets/phash_index.parquet`, ImageHash 4.3.2). Written from `artefacts/coco_gt/d_fire_test_dedup.json`. |
| `dfire_calval_dedup.txt` | 927 | The calibration split after dropping images within Hamming 8 of any official test image and collapsing pHash-identical groups (`make_dfire_dedup.py`). Written from `artefacts/coco_gt/d_fire_calval_dedup.json`. |
| `dfire_train_dedup.txt` | 8,316 | The official training images (minus the 1,722 calval) after the same two rules (`make_dfire_dedup.py`; counts in `artefacts/datasets/d_fire_dedup_yolo.json`: 15,499 - 7,091 near-test - 92 within-split duplicates). Written from the `d_fire_dedup_yolo/train/images` directory listing. |
| `dfire_train_subset.txt` | 8,316 | Size-matched, still leaky control: the first 8,316 of the sorted 15,499 training file names after `random.Random(3407).shuffle` (`make_dfire_sub.py`). Written from the `d_fire_sub_yolo/train/images` listing and reproduced exactly from that rule. |

Every list was checked to be a subset of the corresponding official split
and to have the count stated in the paper. Pyro-SDIS calval/caltest
(2,049 / 2,050), the thesis-set calval/test (590 / 628) and the FIgLib frame
index are defined by the `file_name` fields of `artefacts/coco_gt/*.json` and
by `artefacts/datasets/figlib_index.json`.

## Environment

Python 3.12.11; Ultralytics 8.4.136; PyTorch 2.11.0+cu128, torchvision
0.26.0+cu128; pycocotools 2.0.11; ImageHash 4.3.2; numpy 2.5.2; scipy 1.18.1;
the full pinned list is `requirements.txt` (pip freeze of the paper's venv).
Training and export ran on one NVIDIA GeForce RTX 5070 Ti (16 GB) on Windows
11 with `workers=2` (the machine has 15.8 GB RAM; the reason is recorded in
`docs/TRAINING-PROTOCOL.md`). Protocol: imgsz 640, 60 epochs, batch 16,
patience 15, COCO-pretrained Ultralytics checkpoints, no test-time
augmentation, no per-dataset tuning. Calibration metrics use
`fiveai/detection_calibration` at commit bf59c92 with the patch in
`toolbox_patch/`.

```
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu128
git clone https://github.com/fiveai/detection_calibration && cd detection_calibration
git checkout bf59c92f5416ac4b66a7c2c67b44487777ff2ea4
git apply ../toolbox_patch/detection_calibration_bf59c92.patch && pip install -e .
```

## Datasets

No images or original annotation files are redistributed. Obtain them from
the sources and place them under `data/<name>_yolo/` as described in
`scripts/build_dataset_index.py` and `artefacts/datasets/*.json`:

- D-Fire (CC0 1.0): https://github.com/gaia-solutions-on-demand/DFireDataset — official train/test; the calval split and the derived lists are in `splits/`. The mirror used was count-verified against the official README (`artefacts/datasets/d_fire_yolo.json`, key `notes`).
- Pyro-SDIS (Apache-2.0 / CC-BY): Hugging Face `pyronear/pyro-sdis`; exported with `scripts/parquet_to_yolo.py`; image metadata in `artefacts/datasets/pyro_sdis_image_meta.json`.
- Roboflow *final-fire-project* v4 (Public Domain): Roboflow Universe `brac-university-uuemy/final-fire-project`, COCO export; converted with `scripts/make_thesis_gt.py`. Thesis lineage: http://hdl.handle.net/10361/20208.
- HPWREN FIgLib (Fire Ignition images Library): https://www.hpwren.ucsd.edu/FIgLib/ ; fetched with `scripts/fetch_figlib.sh`, indexed with `scripts/figlib_index.py`. FIgLib imagery: High Performance Wireless Research and Education Network (HPWREN), University of California San Diego, https://www.hpwren.ucsd.edu/

## Detections and checkpoints (Zenodo)

The raw detections and the trained checkpoints exceed what a code repository
should hold, and are archived on Zenodo together with a copy of this
repository; the DOI will be recorded here once minted. The record carries:

| file | contents | raw | upload |
|---|---|---|---|
| `detections.zip` | `detections/` — one JSON per model x split at conf 0.001, max_det 300 (441 files) | 2.906 GB | 531 MB |
| `detections_bnadapt.zip` | `detections_bnadapt/` — batch-norm-adapted exports behind the Table 5 baseline rows (136 files) | 227 MB | 44 MB |
| `detections_bndeconf.zip` | `detections_bndeconf/` — de-confounded TTA exports behind Sec. 5.5: source-BN control, target-BN, Tent (714 files) | 1.001 GB | 189 MB |
| `checkpoints_and_logs.zip` | the 26 `best.pt` with their `args.yaml`, `results.csv` and training curves | 1.372 GB | 1.372 GB |
| `fire-detector-reliability-repo.zip` | `git archive` of this repository at the commit named in the record's `manifest.json` | — | 25 MB |

`last.pt` is not deposited: the paper uses the best-epoch checkpoint only, and
shipping both would double the record.

Checkpoint hashes and best-epoch metrics are in `artefacts/runs_meta/`, so a
downloaded checkpoint can be checked against the one the paper used. All 26
were verified against those hashes when the deposit was built (26/26 matched),
and the record's `manifest.json` carries the SHA-256 of each file above.

Licensing in the record is mixed: the trained weights are AGPL-3.0-or-later
(they were produced with Ultralytics and fine-tuned from its pretrained
checkpoints), while the detection exports, manifests and training logs are
CC BY 4.0. The record's `LICENSE-DEPOSIT.txt` states the operative terms.

## Verification

Every number in the paper is read from the JSON files in `artefacts/` (or is
recomputed from them by a script in `scripts/` whose output is also in
`artefacts/`). Each results paragraph and table in the manuscript source
carries a `% src:` comment naming the artefact file and key it was read from;
the machine-written summaries in `docs/*.md` are the same artefacts rendered
as tables. No number was transcribed from a training log or a console.
